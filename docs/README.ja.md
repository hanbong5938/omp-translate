# omp-translate

[English](../README.md) | [한국어](README.ko.md) | **日本語** | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português](README.pt.md)

バージョン 0.1.7 — OMP（oh-my-pi コーディングエージェント）向けの、特定の言語に依存しない翻訳拡張機能です。

## 概要

- **思考の翻訳**: アシスタントの完了した各思考ブロックを選択した表示言語に翻訳し、TUI 上に別個の `omp-translate-thinking` メッセージとして表示します。元の思考内容とプロバイダーのコンテキストが変更されることはありません。
- **回答の翻訳**（任意、デフォルトはオフ）: メインエージェントの実行が終わると、最終回答を表示言語に翻訳し、原文の下に別の `omp-translate` ボックスとして表示します。元の回答は履歴、セッションファイル、以降の LLM リクエストで変更されません。
- **プロンプトの翻訳**（任意、デフォルトはオフ）: 送信するプロンプトを、送信前にリクエスト言語（デフォルトは英語）へ翻訳します。

原文はどの言語でもよく、複数言語が混在したテキストにも対応します。翻訳先には有効な任意の BCP-47 言語タグを指定できます。

## 必要環境

- OMP（18.10.4 で動作確認済み）
- Bun
- OMP で設定・認証済みのモデル

## インストール

### ローカル開発（リンク）

ローカルのチェックアウトをリンクするには:

```sh
omp plugin link /path/to/omp-translate
```

### ローカルマーケットプレイス

リポジトリには `.omp-plugin/marketplace.json` にマーケットプレイスカタログが含まれています:

```sh
omp plugin marketplace add /path/to/omp-translate
omp plugin discover omp-translate
omp plugin install omp-translate@omp-translate
omp plugin list
```

### ホストされたリポジトリ

プラグインは [hanbong5938/omp-translate](https://github.com/hanbong5938/omp-translate) で公開されています。デフォルトのカタログには掲載されていないため、リポジトリをマーケットプレイスとして追加してからインストールしてください：

```sh
omp plugin marketplace add hanbong5938/omp-translate
omp plugin install omp-translate@omp-translate
```

## 初回起動

インタラクティブ TUI（メインセッションのみ）では、言語選択画面が一度だけ表示されます:

| ラベル | タグ |
|---|---|
| English (en) | `en` |
| 한국어 (ko) | `ko` |
| 日本語 (ja) | `ja` |
| 简体中文 (zh-Hans) | `zh-Hans` |
| 繁體中文 (zh-Hant) | `zh-Hant` |
| Español (es) | `es` |
| Français (fr) | `fr` |
| Deutsch (de) | `de` |
| Português (pt) | `pt` |
| Custom language tag | 任意の BCP-47 タグ（`Intl.getCanonicalLocales` で正規化） |

- キャンセルした場合、翻訳は無効のままとなり、このセッション中に再度尋ねられることはありません。後で `/translate setup` を実行して言語を選択してください。
- プロンプトの翻訳は、`/translate request on` で有効にするまでオフのままです。
- 非インタラクティブモード（`print`、`json`、`rpc`）およびサブエージェントではダイアログは表示されません。`print`/`json` モードでは 1 行のセットアップ案内が stderr に出力されます。`rpc` モードでは代わりに通知が送信されます。

## コマンド

| コマンド | 効果 |
|---|---|
| `/translate` または `/translate status` | 現在の設定と状態を表示 |
| `/translate setup` | 言語選択画面を開く |
| `/translate thinking on\|off` | 思考の翻訳をオン／オフ |
| `/translate answer on\|off` | 回答の翻訳をオン／オフ |
| `/translate request on\|off` | プロンプトの翻訳をオン／オフ |
| `/translate language <tag>` | 表示言語を設定（例: `/translate language pt-BR`） |
| `/translate request-language <tag>` | リクエスト言語を設定（例: `/translate request-language en`） |
| `/translate model <selector\|clear>` | 翻訳モデルを設定（例: `/translate model provider/model` または `/translate model @role`）。`clear` でデフォルトに戻す |
| `/translate request-model <selector\|clear>` | プロンプト翻訳用に別のモデルを設定。`clear` で再び `model` を使用 |

オペランドの不足・過剰、無効な言語タグ、解決できないモデルセレクターはエラーとして拒否されます。その場合、何も保存されません。

## 設定ファイル

設定は `<agent dir>/omp-translate.json` に保存されます。デフォルトの場所は `~/.omp/agent/omp-translate.json` で、パスは OMP のプロファイルと `PI_CONFIG_DIR` に従います。

| キー | デフォルト | 意味 |
|---|---|---|
| `thinking` | `true` | 思考ブロックを翻訳する |
| `answer` | `false` | メインエージェントの最終回答を翻訳する |
| `request` | `false` | 送信するプロンプトを翻訳する |
| `targetLanguage` | `""` | 表示言語（`""` = 未設定） |
| `requestLanguage` | `"en"` | プロンプトの翻訳先言語（空にはできません） |
| `model` | `""` | 翻訳モデルのセレクター（`""` = デフォルト） |
| `requestModel` | `""` | プロンプト翻訳用モデル（`""` = `model` を使用） |

```json
{
  "thinking": true,
  "answer": false,
  "request": true,
  "targetLanguage": "ja",
  "requestLanguage": "en",
  "model": "",
  "requestModel": ""
}
```

プロンプト翻訳の**モデルの優先順位**は `requestModel` → `model` → `@tiny` です。思考と回答の翻訳は `model` → `@tiny` を使用し、`targetLanguage` を共有します。`@tiny` は OMP の tiny モデルロールです。空の値が特定のプロバイダーを固定的に意味することはありません。

言語タグは正規化された形式で保存されます。ファイルを手動で編集した場合、欠けているキーはデフォルト値になります。未知のキー、誤った型、無効な言語タグがあるとファイルは無効になります。ファイルが無効な場合はエラーが表示され、翻訳は無効のままとなり、修正または削除されるまで拡張機能はファイルを上書きしません。

## 動作の詳細

### 思考の翻訳

- 翻訳されるのは完了した思考のみです。つまり、メインエージェントの TUI アシスタントメッセージが終了した後のそのメッセージの思考ブロックで、ツール呼び出し、長さ制限、エラー、中断で終了したメッセージも含みます。ストリーミング中の更新が送信されることはありません。異なる完了済みテキストごとに、翻訳リクエストの開始前に 1.5 秒待機します。秘匿（redacted）された思考、空の思考、ツール引数、回答テキストは翻訳されません。
- 思考ブロックごとに別個の `omp-translate-thinking` メッセージが 1 つ作成されます。メッセージはブロックが完了した順に、エージェントがアイドル状態のときにのみ投稿されます。実行中に完了した結果は、エージェントがアイドルになるまで待機します。思考の翻訳と回答の翻訳の相対的な順序は保証されません。
- 結果の投稿と同時に新しい実行が始まった場合、ホストはメッセージを次のターン用のキューに入れ、次のプロンプトの下に表示されます。投稿によってエージェントのターンが開始されたり誘導（steer）されたりすることはありません。
- 結果はメモリ内にキャッシュされます（最大 500 件）。キャッシュキーにはモデル、翻訳先言語、テキストが含まれます。同一の完了済みテキストは 1 つのリクエストを共有しますが、出現ごとに個別のメッセージが作成されます。
- 設定の変更、セッションの切り替えや分岐、セッションの終了を行うと、保留中の処理がキャンセルされ、まだ投稿されていない結果は破棄されます。投稿済みの翻訳は残ります。
- 翻訳に失敗すると警告（`Thinking translation failed: …`）が表示され、何も投稿されません。
- `Refusal (reasoning_extraction)` が発生すると、そのセッションの残りの思考翻訳を停止し、保留中の処理をキャンセルして警告を一度だけ表示します。代わりに最終回答の翻訳をセッション内で有効にし、拒否が遅れて届いた場合は直近の完了済み回答も翻訳します。保存済み設定は変更しません。`/translate status` で状態を確認でき、`/translate answer off` で代替翻訳を無効にできます。セッションの切り替え・分岐・終了で両方の一時設定が解除されます。他のエラーではこの動作は発生しません。
- 各翻訳には 20 秒の期限があり、再試行と共有されます（「再試行」を参照）。
- ホストは投稿された各翻訳を保存し、再開時に再表示します。この拡張機能は回答の翻訳と同様に、これらのメッセージをすべてのモデルリクエストから除外します。再開時に、翻訳メッセージのない過去の思考は翻訳されません。

### プロンプトの翻訳

- 翻訳は入力の送信時に行われます。翻訳されたテキストがセッション履歴に保存され、あなたのメッセージとして表示されます。
- ホストのコマンド構文は翻訳されません: スラッシュコマンド（`/…`）、シェルコマンド（`!…`）、Python コマンド（`$ …`、空白が続く `$$ …`）、キューマーカー（`->`、`=>`）。先頭の空白は無視されます。画像の添付はそのまま残されます。
- 翻訳結果自体がホストのコマンド構文のように見える場合は、警告が表示され、原文が送信されます。
- 翻訳に失敗した場合は、警告が表示され、原文が送信されます。
- プロンプトの翻訳中にセッションが切り替えられたり分岐したりした場合、そのプロンプトは警告とともに破棄されます。新しいセッションで再送信してください。シャットダウン時には、保留中のプロンプトは通知なく破棄されます。

### 回答の翻訳

- `/translate answer on` で有効にします。TUI のメインエージェントが正常に完了した最終回答のみを翻訳します。サブエージェント、非インタラクティブモード（`print`、`json`、`rpc`）、リトライ／継続実行、ツール呼び出しで終わったターンは翻訳しません。
- 翻訳は非同期で行われ、新しいエージェントターンは開始されません。期限は 60 秒です。エージェントがビジーな間に完了した翻訳は、次のメイン実行が終わってアイドルになったときに表示されます。
- 60 秒の期限は再試行と共有されます（「再試行」を参照）。
- セッションの切り替え、分岐、終了を行うと、保留中の回答翻訳は破棄されます。
- すでに翻訳先言語で書かれていて結果が原文と同じ場合は表示しません。翻訳やプレースホルダーの検証に失敗した場合は警告が表示され、回答の翻訳は省略されます。
- 翻訳は `display: true` の独立したカスタムメッセージ（`customType` `omp-translate`）としてホストがセッションファイルに保存するため、セッション再開時にも表示されます。
- プラグインは回答翻訳の設定にかかわらず、このメッセージを常にプロバイダーのコンテキストから除外します。この除外はプラグインが読み込まれている場合にのみ機能するため、翻訳を含むセッションを再開するときはプラグインを無効にしないでください。無効にすると、ホストは保存された翻訳をモデルに送信します。

### コードの保持

- フェンス付きコードブロックとインラインコードは翻訳前にプレースホルダーへ置き換えられ、翻訳後にバイト単位で正確に復元されます。
- モデルがプレースホルダーを削除または重複させた場合、その翻訳は拒否され、一度だけ再試行されます（「再試行」を参照）。再試行も拒否された場合、プロンプトでは原文が送信され、思考では失敗が表示され、回答では警告が表示されて翻訳は投稿されません。
- その他の識別子やパスは、モデルへの指示によってのみ保護されます。完全な保持や意味的な等価性は保証されません。
- 原文は、翻訳対象のテキストとして扱うようモデルに指示する枠組みで囲まれます。この枠組みはガイダンスであり、セキュリティ境界ではありません。

### 再試行

- すべての翻訳（思考、回答、プロンプト）は、1 つの共有期限（20 秒、回答は 60 秒）内で最大 2 回試行されます。再試行では原文を再送信します。
- コードのプレースホルダーが欠落または重複している場合、または出力に翻訳先言語に属さない文字体系の文字が含まれている場合に再試行します。ラテン文字は常に許容されます（識別子、パス、英語の用語）。漢字は韓国語・日本語・中国語、かなは日本語、注音符号（Bopomofo）は中国語の翻訳先で許容されます。例: 韓国語のコミットメッセージが残ったままの英語訳は再試行されます。
- 言語の再試行では、引用テキスト、タイトル、コミットメッセージも翻訳するよう指示を追加します。2 つの結果のうち、外国の文字体系の文字が少ない方が表示されます。再試行が失敗またはタイムアウトした場合は、最初の結果が使われます。
- このチェックは文字体系のみに基づきます。文字体系が同じで言語が誤っている出力（英語の代わりにスペイン語、または翻訳先が韓国語なのに未翻訳の英語）は検出されません。タグから文字体系を判定できない言語はチェックされません。

## プライバシーとコスト

- 思考の翻訳では完了した思考テキストが、回答の翻訳（有効時）では最終回答が、選択したモデルプロバイダーに送信されます。プロンプトの翻訳ではプロンプトが送信されます。いずれもそのプロバイダーの利用枠を消費します。
- 拡張機能が直接書き込むファイルは設定ファイルのみです。投稿された思考の翻訳と回答の翻訳は、ホストによって別個のカスタムメッセージとしてセッションファイルに保存されます。
- 認証情報は OMP のモデルレジストリによって解決されます。拡張機能はトークンストアを読み取らず、認証情報、原文、訳文をログに記録しません。

## 制限事項

- 入力フックは、OMP が提供するとおり、インタラクティブ入力と RPC 入力に適用されます。
- 思考と回答の翻訳は TUI のメインエージェントのみが対象です。回答の翻訳は完了した最終回答のみが対象で、ツール呼び出しを含むターンの途中のテキストは翻訳されません。
- 思考の翻訳は思考の表示状態とは無関係です。`hideThinkingBlock: true`（または `--hide-thinking`）で非表示にした思考も翻訳され、別個のメッセージとして表示されます。停止するには `/translate thinking off` を使用してください。
- 思考と回答の翻訳は永続化されます。再開時にモデルのコンテキストから除外されるよう、拡張機能を読み込んだままにしてください。このバージョンより前に記録されたセッションの思考や、思考の翻訳がオフだった間の思考は、遡って翻訳されません。
- `answer` キーに対応していない旧バージョンは厳格なスキーマにより設定ファイルを拒否します。ダウングレードする前に `answer` キーを削除してください。
