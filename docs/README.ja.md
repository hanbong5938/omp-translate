# omp-translate

[English](../README.md) | [한국어](README.ko.md) | **日本語** | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português](README.pt.md)

バージョン 0.1.0 — OMP（oh-my-pi コーディングエージェント）向けの、特定の言語に依存しない翻訳拡張機能です。

## 概要

- **思考の翻訳**: アシスタントの各思考ブロックを選択した表示言語に翻訳し、TUI 上で原文の下に訳文を表示します。元の思考内容とプロバイダーのコンテキストが変更されることはありません。
- **プロンプトの翻訳**（任意、デフォルトはオフ）: 送信するプロンプトを、送信前にリクエスト言語（デフォルトは英語）へ翻訳します。

原文はどの言語でもよく、複数言語が混在したテキストにも対応します。翻訳先には有効な任意の BCP-47 言語タグを指定できます。

## 必要環境

- OMP（18.10.4 で動作確認済み）
- Bun
- OMP で設定・認証済みのモデル

## インストール

### ローカル開発（リンク）

ローカルのチェックアウトをリンクするには:

```sh
omp plugin link /path/to/omp-translate
```

### ローカルマーケットプレイス

リポジトリには `.omp-plugin/marketplace.json` にマーケットプレイスカタログが含まれています:

```sh
omp plugin marketplace add /path/to/omp-translate
omp plugin discover omp-translate
omp plugin install omp-translate@omp-translate
omp plugin list
```

### ホストされたリポジトリ

プラグインは [hanbong5938/omp-translate](https://github.com/hanbong5938/omp-translate) で公開されています。デフォルトのカタログには掲載されていないため、リポジトリをマーケットプレイスとして追加してからインストールしてください：

```sh
omp plugin marketplace add hanbong5938/omp-translate
omp plugin install omp-translate@omp-translate
```

## 初回起動

インタラクティブ TUI（メインセッションのみ）では、言語選択画面が一度だけ表示されます:

| ラベル | タグ |
|---|---|
| English (en) | `en` |
| 한국어 (ko) | `ko` |
| 日本語 (ja) | `ja` |
| 简体中文 (zh-Hans) | `zh-Hans` |
| 繁體中文 (zh-Hant) | `zh-Hant` |
| Español (es) | `es` |
| Français (fr) | `fr` |
| Deutsch (de) | `de` |
| Português (pt) | `pt` |
| Custom language tag | 任意の BCP-47 タグ（`Intl.getCanonicalLocales` で正規化） |

- キャンセルした場合、翻訳は無効のままとなり、このセッション中に再度尋ねられることはありません。後で `/translate setup` を実行して言語を選択してください。
- プロンプトの翻訳は、`/translate request on` で有効にするまでオフのままです。
- 非インタラクティブモード（`print`、`json`、`rpc`）およびサブエージェントではダイアログは表示されません。`print`/`json` モードでは 1 行のセットアップ案内が stderr に出力されます。`rpc` モードでは代わりに通知が送信されます。

## コマンド

| コマンド | 効果 |
|---|---|
| `/translate` または `/translate status` | 現在の設定と状態を表示 |
| `/translate setup` | 言語選択画面を開く |
| `/translate thinking on\|off` | 思考の翻訳をオン／オフ |
| `/translate request on\|off` | プロンプトの翻訳をオン／オフ |
| `/translate language <tag>` | 表示言語を設定（例: `/translate language pt-BR`） |
| `/translate request-language <tag>` | リクエスト言語を設定（例: `/translate request-language en`） |
| `/translate model <selector\|clear>` | 翻訳モデルを設定（例: `/translate model provider/model` または `/translate model @role`）。`clear` でデフォルトに戻す |
| `/translate request-model <selector\|clear>` | プロンプト翻訳用に別のモデルを設定。`clear` で再び `model` を使用 |

オペランドの不足・過剰、無効な言語タグ、解決できないモデルセレクターはエラーとして拒否されます。その場合、何も保存されません。

## 設定ファイル

設定は `<agent dir>/omp-translate.json` に保存されます。デフォルトの場所は `~/.omp/agent/omp-translate.json` で、パスは OMP のプロファイルと `PI_CONFIG_DIR` に従います。

| キー | デフォルト | 意味 |
|---|---|---|
| `thinking` | `true` | 思考ブロックを翻訳する |
| `request` | `false` | 送信するプロンプトを翻訳する |
| `targetLanguage` | `""` | 表示言語（`""` = 未設定） |
| `requestLanguage` | `"en"` | プロンプトの翻訳先言語（空にはできません） |
| `model` | `""` | 翻訳モデルのセレクター（`""` = デフォルト） |
| `requestModel` | `""` | プロンプト翻訳用モデル（`""` = `model` を使用） |

```json
{
  "thinking": true,
  "request": true,
  "targetLanguage": "ja",
  "requestLanguage": "en",
  "model": "",
  "requestModel": ""
}
```

プロンプト翻訳の**モデルの優先順位**は `requestModel` → `model` → `@tiny` です。思考の翻訳は `model` → `@tiny` を使用します。`@tiny` は OMP の tiny モデルロールです。空の値が特定のプロバイダーを固定的に意味することはありません。

言語タグは正規化された形式で保存されます。ファイルを手動で編集した場合、欠けているキーはデフォルト値になります。未知のキー、誤った型、無効な言語タグがあるとファイルは無効になります。ファイルが無効な場合はエラーが表示され、翻訳は無効のままとなり、修正または削除されるまで拡張機能はファイルを上書きしません。

## 動作の詳細

### 思考の翻訳

- 異なる思考テキストごとに、翻訳リクエストの開始前に 1.5 秒待機します。ストリーミング中の異なるスナップショットはそれぞれ独立したリクエストとなるため、長いストリーミングブロックでは複数回のモデル呼び出しが発生することがあります。
- 結果はメモリ内にキャッシュされます（最大 500 件）。キャッシュキーにはモデル、翻訳先言語、テキストが含まれます。同一のテキストを表示するビューは 1 つのリクエストを共有します。
- 設定の変更、セッションの切り替えや分岐、セッションの終了を行うと、保留中の処理がキャンセルされ、画面上の既存の翻訳がクリアされます。
- 各翻訳には 20 秒の期限があります。

### プロンプトの翻訳

- 翻訳は入力の送信時に行われます。翻訳されたテキストがセッション履歴に保存され、あなたのメッセージとして表示されます。
- ホストのコマンド構文は翻訳されません: スラッシュコマンド（`/…`）、シェルコマンド（`!…`）、Python コマンド（`$ …`、空白が続く `$$ …`）、キューマーカー（`->`、`=>`）。先頭の空白は無視されます。画像の添付はそのまま残されます。
- 翻訳結果自体がホストのコマンド構文のように見える場合は、警告が表示され、原文が送信されます。
- 翻訳に失敗した場合は、警告が表示され、原文が送信されます。
- プロンプトの翻訳中にセッションが切り替えられたり分岐したりした場合、そのプロンプトは警告とともに破棄されます。新しいセッションで再送信してください。シャットダウン時には、保留中のプロンプトは通知なく破棄されます。

### コードの保持

- フェンス付きコードブロックとインラインコードは翻訳前にプレースホルダーへ置き換えられ、翻訳後にバイト単位で正確に復元されます。
- モデルがプレースホルダーを削除または重複させた場合、その翻訳は拒否されます。プロンプトの場合は原文が送信されます。思考の場合は失敗が表示されます。
- その他の識別子やパスは、モデルへの指示によってのみ保護されます。完全な保持や意味的な等価性は保証されません。
- 原文は、翻訳対象のテキストとして扱うようモデルに指示する枠組みで囲まれます。この枠組みはガイダンスであり、セキュリティ境界ではありません。

## プライバシーとコスト

- 思考の翻訳では、表示されている思考テキストが選択したモデルプロバイダーに送信されます。プロンプトの翻訳ではプロンプトが送信されます。どちらもそのプロバイダーの利用枠を消費します。
- 拡張機能が書き込むファイルは設定ファイルのみです。翻訳はメモリ内にのみ保持されます。
- 認証情報は OMP のモデルレジストリによって解決されます。拡張機能はトークンストアを読み取らず、認証情報、原文、訳文をログに記録しません。

## 制限事項

- 入力フックは、OMP が提供するとおり、インタラクティブ入力と RPC 入力に適用されます。
- アシスタントの応答は翻訳されません。
- 思考の翻訳は、TUI で思考ブロックが表示されている間のみ描画されます。`hideThinkingBlock: true`（または `--hide-thinking`）の場合は、何も翻訳・表示されません。表示は `Ctrl+T` で切り替えられます。
- 翻訳は永続化されません。再起動後、思考は再度翻訳されます。
